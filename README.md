# Audiobook QC — проверка озвучки аудиокниг по тексту

[Русский](README.md) · [English](README.en.md) · [Скачать приложение](https://github.com/kus142kus/AudiobookQC/releases) · [Сообщить об ошибке](https://github.com/kus142kus/AudiobookQC/issues)

**Audiobook QC** — локальное приложение для дикторов, чтецов, редакторов и издателей. Сравнивает запись аудиокниги с рукописью, помогает находить предполагаемые оговорки, замены и пропуски слов, повторы и отдельные проблемы звука. Подготавливает **Word-отчёты с таймкодами**, чтобы быстро перейти к месту, которое нужно прослушать или перезаписать.

> **Стадия проекта — 1.0 Release Candidate (RC2), не стабильная 1.0.** Автоматическая сборка Windows x64 и macOS Apple Silicon успешно прошла в GitHub Actions (запуск №38, 25 ноября 2026 года). Запуск на Windows подтверждён, обработка первой части реальной записи подтверждена. Установка на настоящем Mac M4 и точность на размеченных аудиозаписях пока требуют испытаний. Нельзя гарантировать нахождение всех ошибок.

## Что умеет

- Сравнивает русскоязычное аудио с текстом `DOCX` или `TXT`.
- Поддерживает длительные записи: разбивает их на части и сохраняет промежуточные результаты.
- Использует локальный Whisper Medium и независимую выборочную перепроверку GigaAM. **Две модели не гарантируют правильный ответ**.
- Показывает вероятные оговорки, пропуски и повторения; отделяет редакционные варианты от более значимых расхождений.
- Позволяет прослушать подозрительный фрагмент, отметить «Исправлено» или «Не ошибка».
- Экспортирует `.docx` после каждой завершённой части и итоговый Word после завершения всей проверки.
- Дополнительно сигнализирует о возможных щелчках, шуме и иных звуковых событиях. **Это лишь кандидаты на проверку на слух**.
- Обрабатывает записи и рукописи **локально**, без отправки содержимого в облако. Windows требуется подключение к интернету **только для первоначального скачивания модели установщиком**.

## Как проходит первая проверка

1. Подготовьте **один аудиофайл** и **соответствующий ему текст**. Если оба лежат в одной папке и там нет других аудио или рукописей, можно выбрать папку целиком.
2. Откройте **«Новая проверка» → «Выбрать папку с двумя файлами»**. Либо выберите аудио и документ по отдельности.
3. Укажите период промежуточных Word-отчётов (обычно 10–20 минут) и нажмите **«Начать проверку»**.
4. По готовности части откройте замечания, прослушайте их в приложении и проставьте отметки. Включите **«Показывать сомнительные»**, чтобы посмотреть необязательные кандидаты.
5. Скачайте **Word** для готовой части; после полного завершения — **«Сохранить итоговый Word»**.

Рекомендуем начать с **5–10 минут** записи. Скорость распознавания зависит от процессора, памяти и длительности файла. Для нескольких часов может потребоваться существенно больше реального времени.

## Насколько точна проверка?

Программа показывает **подозрения**, а не автоматически установленные ошибки. Сравнение речи с текстом может ошибаться из-за произношения, имён, акцентов и качества записи. Ударения и интонация проверяются **экспериментально**, поэтому по одному отчёту нельзя объявлять их ошибочными. Пропущенные программой ошибки тоже возможны — при ответственной работе необходим контроль человеком.

## Как выглядит результат проверки

| Таймкод (пример) | В рукописи | Предположительно прочитано | Действие |
| --- | --- | --- | --- |
| `00:05:24` | «он не вернулся» | «он вернулся» | Проверить пропуск отрицания |
| `00:10:21` | «со мною» | «со мной» | Редакционный вариант — не обязательно ошибка |
| `00:12:51` | — | Возможный посторонний звук | Сверить на слух: акустическая метка не является доказательством |

*Это вымышленные примеры для демонстрации, а не результаты проверки чьей-либо книги.* Приоритет — существенные замены, пропуски, повторения и отрицания. Спорные однословные отличия остаются для перепроверки, а не автоматически объявляются ошибками.

## Дополнительные платформы — отдельные испытания

Новые проверочные задания **не вмешиваются в успешно собранные Windows x64 и Mac Apple Silicon**. В разделе [дополнительных платформ](docs/Дополнительные-платформы.md) описан **один ручной запуск** для Linux x64, Linux ARM64, пробной Mac Intel сборки и проверки x64-эмуляции на Windows 11 ARM64. **Это не означает, что версии для этих ОС уже готовы**: артефакт появляется только после прохождения соответствующего реального задания.

## Конфиденциальность и обратная связь

По замыслу приложения, содержимое записей и текстов не загружается в облачные сервисы; анализ выполняется на устройстве. Не прикрепляйте в публичные GitHub Issues коммерческие рукописи, личные записи и другие конфиденциальные материалы. Для обращения обычно достаточно версии ОС, описания действий, снимка экрана **без личных данных** и обезличенного фрагмента отчёта.

## Для разработчиков

Исходники: `src/audiobook_qc/`; интерфейс: `web/`; сборки: `.github/workflows/`. Автотесты: `python -m unittest discover -s tests -v`. Основной release workflow собирает **Windows x64 и macOS Apple Silicon**. Linux x64 и Linux ARM64 тестируются **только отдельно, по ручному запуску**; их артефакты не включены в публичный выпуск.

**Открытая разработка:** вклад и сообщения о найденных проблемах приветствуются. Проверка лицензий включённых моделей, подпись/нотаризация публичного Mac-приложения и реальные тесты на оборудовании остаются необходимыми перед стабильным выпуском.
