# Руководство пользователя Audiobook QC

Версия: **1.0 RC2 (предварительная)**. Для Windows 10/11 x64 и Mac Apple Silicon; Mac Intel, Windows ARM64 и Linux пока не объявлены поддерживаемыми пользовательскими версиями.

## 1. Что подготовить

- **Аудиозапись**: MP3, WAV, M4A, FLAC (также поддерживаются AAC, OGG и MP4; совместимость конкретного файла зависит от кодека).
- **Рукопись**: DOCX или TXT. Текст должен соответствовать **именно загруженному фрагменту**, а не другой редакции книги.
- Для первой пробы возьмите 5–10 минут записи. Это позволит проверить запуск, скорость и качество отчёта до многочасовой обработки.

Самый простой случай: одна папка, внутри `Фрагмент.mp3` и `Фрагмент.docx` без других аудиофайлов и рукописей. Вложенные папки приложение само не обходит. Если в папке несколько подходящих файлов, выберите нужные вручную.

## 2. Запустить проверку

1. Откройте программу → **«Новая проверка»**.
2. Нажмите **«Выбрать папку с двумя файлами»** или отдельно **«Выбрать файл»** для аудио и рукописи.
3. При необходимости внесите сложные имена и термины в поле **«Имена, термины и ударения»**. Ударение можно отметить знаком `´` после гласной, но функция экспериментальная.
4. В выпадающем списке **«Отчёт каждые»** выберите 5, 10, 20, 30 или 60 минут. Для длинной книги обычно удобно 20 минут.
5. Нажмите **«Начать проверку»**. Не удаляйте и не перемещайте созданные папки проекта во время обработки.

## 3. Читать результаты

- **«Ход проверки»** показывает длительность проанализированного материала, а не время, которое прошло на часах.
- **«Отчёты по частям» → «Word»**: сохраняет готовый отчёт, не дожидаясь завершения всей книги.
- **«Замечания»**: нажмите строку, чтобы увидеть предполагаемый вариант из аудио, правильный текст и временную отметку.
- **«Показывать сомнительные»**: дополнительные кандидаты, не подтверждённые обеими речевыми моделями. Они требуют особенно внимательного прослушивания.
- **«Слушать»**, `−10 с`, `+10 с` и **«Скорость»** помогают перепроверять замечание.
- Отметьте **«Исправлено»** или **«Не ошибка»**. Вторая отметка убирает замечание из списка исправлений, но не удаляет его из истории проекта.

Отчёт может включать редакционные отличия (например, «мною/мной») и предположения о звуковых событиях. Это **не доказанные ошибки диктора**.

## 4. Пауза и окончательный Word

- **«Приостановить»**: запросить остановку. Дождитесь изменения статуса; не выключайте компьютер посреди записи промежуточных файлов.
- **«Продолжить»**: возобновить проект после остановки, если файлы и данные проекта сохранились.
- После завершения всех частей появится **«Сохранить итоговый Word»**.
- Кнопка **«Папка с отчётами»** открывает сохранённые результаты проекта.

## 5. Как оценивать качество

При проверке исходного текста важнее всего: пропущенные/лишние части предложений, отрицания («не»), цифры и имена, замены слов со сменой смысла, дубли и внезапные оговорки. Небольшие особенности произношения не обязаны считаться ошибками. Но нельзя автоматически исключать короткие слова: **одно «не» способно перевернуть смысл фразы**.

В Word указаны **предполагаемые** нарушения. Прослушайте контекст вокруг каждого таймкода. Программа может **пропускать ошибки** и **ошибочно отмечать правильное чтение**. Ударения/интонация и помехи — отдельная категория предупреждений.

## 6. Если что-то пошло не так

| Ситуация | Что сделать |
| --- | --- |
| Не удалось выбрать папку | Проверьте, что в ней ровно одно аудио и один DOCX/TXT; иначе выбирайте файлы раздельно |
| Проверка очень долгая | Начните с короткого фрагмента, затем увеличивайте длительность; скорость зависит от CPU/ОЗУ |
| Не появился итоговый Word | Итоговый файл доступен **после завершения** всех частей; промежуточные Word доступны раньше |
| Выбранный фрагмент не совпадает с рукописью | Выберите точную редакцию и соответствующий кусок аудио, иначе замечания будут недостоверными |
| Найдено слишком много спорных ошибок | Прослушивайте только значимые, включайте/выключайте «Показывать сомнительные» |
| Mac блокирует первый запуск | Убедитесь, что скачали официальный файл из Releases; используйте только штатный способ macOS, не отключайте Gatekeeper глобально |
| Windows-установка не скачала модель | Проверьте интернет, наличие соответствующего `AQC-Model.zip` **в том же GitHub Release**; если его нет, обратитесь разработчику |

**Удаление проекта** внутри приложения может удалить его рабочие копии аудио, текста и отчётов. Оригинальные исходные файлы вне проекта должны сохраняться, но перед удалением убедитесь, что нужные Word-файлы экспортированы.

## 7. Помощь проекту

Откройте [GitHub Issues](https://github.com/kus142kus/AudiobookQC/issues). Укажите ОС, её версию, архитектуру процессора, примерно какой файл проверяли, на каком шаге произошёл сбой и что ожидали увидеть. **Не загружайте публично рукописи, аудио или логи с личными данными**. Для Mac M4 полезны версия macOS, объём ОЗУ и обезличенный скриншот ошибки.
