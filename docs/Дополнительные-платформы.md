# Проверки дополнительных операционных систем

**Текущая основная версия:** Windows 10/11 x64 и Mac Apple Silicon (включая M4), сборка GitHub Actions №38 успешна. Это ещё не означает прохождение испытаний на реальных компьютерах и не делает RC2 стабильным выпуском.

## Один ручной запуск для четырёх экспериментов

Новый сценарий **`Audiobook QC - additional platforms PREVIEW (manual)`** запускается в Actions отдельно от основного `build.yml`. Он **автоматически запустится один раз при загрузке самого файла сценария** и позже доступен для ручного перезапуска. Не публикует стабильные релизы и не меняет исходные настройки успешной Windows/Mac-сборки.

| Платформа | Что запускается | Когда можно считать готовой |
| --- | --- | --- |
| Linux x64 | Нативный Linux runner → зависимости → тесты → Qt-окно → 2 речевые + акустическая модель → PyInstaller → архив | При успешной сборке появляется `AQC-Linux-x64-PREVIEW`; нужен реальный тест обработки и Word |
| Linux ARM64 | То же на настоящем AArch64 runner, проверка бинарника | `AQC-Linux-ARM64-PREVIEW` появляется только если все этапы успешны; нужен тест на устройстве |
| Mac Intel | Отдельный Linux-сборщик безопасно конвертирует проверенные веса GigaAM в `safetensors` с PyTorch 2.8; Intel Mac получает только безопасный формат, использует `torch/torchaudio 2.2.2` и проверяет настоящий инференс | `AQC-Mac-Intel-PREVIEW` создаётся **только если** старая версия библиотеки совместима и все проверки пройдены; это ещё не нотариализованный DMG |
| Windows 11 ARM64 | На ARM runner скачивается **Windows-установщик** из успешной x64-сборки и проверяется его запуск. Загрузчик Inno Setup сам может быть 32-битным (PE 0x014c), даже когда полезная нагрузка x64; заголовок установщика не доказывает архитектуру приложения | Результат только в `AQC-Windows-ARM64-EMULATION-SMOKE`; **это не нативный пакет, не установка и не проверка моделей** |

### Как запустить

1. Откройте [Actions](https://github.com/kus142kus/AudiobookQC/actions).
2. Выберите `Audiobook QC - additional platforms PREVIEW (manual)`.
3. Нажмите **Run workflow**, оставьте `main` и пустое поле `windows_x64_run_id` (тогда Windows ARM выберет последнюю успешную Windows x64 сборку) → **Run workflow**.
4. Внутри запуска раскройте все задания. Зелёная галочка означает успешное прохождение **заявленных** проверок этого задания; красный крестик — отсутствие совместимого рабочего пакета.
5. Скачивайте `PREVIEW` из Artifacts только после зелёного задания; для Windows ARM64 будет лишь диагностический текст.

Задания Linux также доступны отдельно через старые `linux-preview.yml` и `linux-arm64-preview.yml`; для них не нужно менять основной workflow.

### Почему нельзя объявить поддержку всех ОС заранее

- `CTranslate2` распространяет готовые Windows wheel прежде всего для x64; на ARM64 Python backend требует отдельного портирования. Windows 11 ARM64 поддерживает эмуляцию x64-программ, но запуск установщика **не доказывает работу всей системы распознавания**.
- PyTorch 2.8 не предоставляет официальный Intel-macOS wheel. Поэтому эксперимент не пытается снять проверку безопасности загрузки старого `.bin`: веса GigaAM сначала конвертируются на Linux с PyTorch 2.8 и `weights_only=True`, а Intel загружает только `model.safetensors`. Даже это не гарантирует совместимость старого PyTorch с текущим Transformers — её должен подтвердить настоящий инференс.
- Linux tar.gz — не универсальный установщик. Для звукового плеера требуется системная PortAudio (`libportaudio2` на Ubuntu); при сборке GitHub Actions она устанавливается явно. Для публичного статуса нужны испытания на реальной Linux-системе и надёжная упаковка системных зависимостей.

**Условия для стабильной 1.0:** реальное устройство с нужным CPU, полная установка, офлайн-распознавание (включая вторую модель), проверка 5–10 минут записи, Word-отчёт, продолжение длинной записи, лицензии и публикация корректного подписанного файла там, где это требуется.
