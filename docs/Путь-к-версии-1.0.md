# AudiobookQC — условия готовности к версии 1.0 (на 24 ноября 2026)

## Текущий статус

**ВЕРСИЯ 1.0 ПОКА НЕ ГОТОВА К ПУБЛИКАЦИИ.** После получения полного архива
GitHub в работе находится уже **целый исходный проект**, а не отдельный патч.
Локально прогнано **170 автоматических тестов (170 прошли)**, выполнены
синтаксические проверки и статический preflight. Этот архив **не содержит
моделей Whisper/GigaAM/YAMNet или готовых EXE/DMG**: модели скачиваются
только на этапе GitHub Actions. Поэтому без сборки на целевых OS и ручной
проверки реальных озвучек невозможно обещать точность, скорость или работу
на конкретном M4. Не меняйте текущий тег v1.0.0-rc.1 на `v1.0.0`
только ради названия.

В этом интегрированном исходном коде дополнительно исправлены: исключение
отклонённых замечаний из корректурного Word; импорт пары файлов из папки;
ручное сохранение полного Word после завершения; проверка свободного места;
перепроверка структуры сохранённых сегментов; извлечение таймкодов из
реально создаваемых Word-таблиц; честные счётчики основного списка;
проверки документации и полноценная регрессия пользовательского пути.
Текущий статус: **1.0 release candidate / v1.0.0-rc.1**. Это не стабильный публичный релиз.

## Что добавлено в этом обновлении

1. Независимый инструмент `scripts/benchmark_readings.py`: сравнивает
   подтверждённые реальные ошибки с замечаниями программы с допуском по времени
   и строгим отношением один-к-одному. Считает precision, recall, F1,
   ложные тревоги в час, отдельно показывает пропущенные ошибки и ложные
   предупреждения. Экспорт JSON + Word.
2. Извлечение возможных замечаний из Word в CSV для ручной валидации —
   `--extract-docx отчет.docx --output-csv замечания.csv`. Все извлечённые
   строки помечаются `review`, **не** как подтверждённые ошибки.
3. Защита релиза: публикация проверяет **оригинальные** SHA-256, созданные на
   машине сборки, и больше не переписывает их прямо перед проверкой.
4. Проверка совпадения версии Windows-установщика и GitHub Release, а также
   отказ от небезопасных путей и дублей в архиве модели.
5. Автоматические регрессионные тесты этих механизмов.

## Действительно необходимые испытания перед 1.0

**Этап A — инфраструктура.** Обе CI-сборки зелёные. Windows `AQC-Setup.exe`
полностью устанавливает программу и модель без отдельной распаковки архива;
после установки интернет не нужен. Mac `.dmg` запускается на настоящем M4;
проверены размер пакета <2 GiB, ARM64, наличие всех моделей, экспорт DOCX,
удаление и повторная установка без потери проектов.

**Этап B — качество.** Нужны минимум три независимых отрывка русской художественной
озвучки по 10–20 минут, а также отдельная запись 2–6 часов. Для первого этапа
известны настоящие, вручную размеченные ошибки: неверные слова, отрицания «не»,
числа, имена, пропуски, повторы/перезаписи. И отдельные *правильные* места с
омофонией «о/а», «е/я», переносами, знаками препинания и вариантами написания.
Не подменять ручную проверку фиктивным TTS/ASR-совпадением.

Предварительные **целевые**, а не достигнутые показатели для существенных ошибок:
precision ≥90%, recall ≥90%, ложных тревог не более 3 за час; отдельно вести
число пропущенных отрицаний и критических смысловых замен (цель — ноль на
контрольном наборе). Для художественной дикторской работы пороги уточняются
после проб с папой. Звуковые помехи и ударения оценивать отдельно — нельзя
считать их подтверждёнными только по эвристике.

**Этап C — эксплуатация.** Программа должна не зависать на больших файлах и при
долгом ожидании, продолжать незавершённую задачу, не портить оригиналы,
корректно отображать таймкоды за 6 часов, сохранять частичные отчёты, не
терять результаты после перезапуска, уметь работать при отсутствии сети.
Проверить хотя бы 2 различных компьютера Windows и Mac M4. Не требовать от
папы GitHub, Python или командной строки.

**Этап D — выпуск.** Обязательны ручное подтверждение прав на распространение
каждой версии модели и библиотек, сведения о сборках, инструкции на русском,
проверка репутации установщиков. Неподписанная программа может не пройти
Gatekeeper/SmartScreen; не предлагайте отключать защиту системы.

**Рабочий порядок**: полный репозиторий уже получен и локальный набор
регрессий проходит. Теперь необходимо загрузить интегрированные исходники
в GitHub и дождаться CI на Windows-x64 и Mac Apple Silicon; затем проверить
реальные установщики на компьютере автора и Mac M4 папы. После этого
провести тест с настоящей размеченной озвучкой и лишь затем присваивать
стабильный релиз 1.0.

## Пример инструмента оценки

```bash
python scripts/benchmark_readings.py \
  --truth examples/accuracy/truth.csv \
  --findings examples/accuracy/findings.csv \
  --duration-hours 0.25 \
  --output benchmark.json --docx benchmark.docx
```

Для реальной проверки помести CSV и DOCX в личную локальную папку вне репозитория,
подставь абсолютные пути. Файл разметки нельзя подделывать ради успешного теста.
Результат сравнения по **таймкоду** является лишь первичным скринингом.
Редактор должен вручную убедиться, что каждая засчитанная находка относится
к правильной фразе и именно к той ошибке (не к соседней). Если этого нет,
цифры показывают только покрытие по времени, но не редакторскую достоверность.
