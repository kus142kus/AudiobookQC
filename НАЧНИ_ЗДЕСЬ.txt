AUDIOBOOK QC 0.6 — КАК ЗАГРУЗИТЬ И ПРОВЕРИТЬ

ВАЖНО: ЭТО ИСХОДНИКИ, НЕ ГОТОВАЯ ПРОГРАММА.
Чтобы получить программы для Windows и Mac M4, GitHub Actions должен успешно
собрать два пакета С ВКЛЮЧЁННЫМИ НЕЙРОМОДЕЛЯМИ. Интернет нужен на GitHub
во время сборки; после успешной упаковки программа должна работать локально.

1. Один раз установите GitHub Desktop: https://desktop.github.com/
2. File -> Clone repository -> URL: https://github.com/kus142kus/AudiobookQC
3. В GitHub Desktop: Repository -> Show in Explorer. Откроется КОРЕНЬ
   локальной копии репозитория (рядом с README.md).
4. Распакуйте этот ZIP в отдельную папку. Скопируйте ВСЁ СОДЕРЖИМОЕ
   (включая скрытую .github) в корень клонированного репозитория.
   Подтвердите замену файлов. Старую папку web можно удалить — веб-версия
   в 0.6 не используется. Удалите старые дублирующие инструкции при желании.
5. В GitHub Desktop: Changes -> Summary: "Audiobook QC 0.6 dual model offline"
   -> Commit to main -> Push origin. Не загружайте аудио или тексты книг.
6. В браузере https://github.com/kus142kus/AudiobookQC/actions
   откройте новый workflow "Audiobook QC 0.6 - native offline desktop builds".
   Ожидайте двух успешных заданий: Windows-x64 и Mac-Apple-Silicon.
   ВАЖНО: если красный крест, пакет не готов; просмотрите ошибку в Logs.
7. Внутри успешного запуска внизу -> Artifacts. Скачайте Windows и Mac,
   распакуйте ZIP, Windows-программу — в отдельную папку, DMG — на Mac.
8. Windows: запустите AudiobookQC.exe; Mac M4: AudiobookQC.app из DMG.
   Python и браузер не требуются. Если приложение сообщает об отсутствующей
   модели или не запускается, сборка не прошла полноценно — сообщите текст
   ошибки/скриншот. Не удаляйте старую 0.2.1 и её сохранённые результаты.

ПЕРВАЯ ПРАКТИЧЕСКАЯ ПРОВЕРКА (НЕ ШЕСТЬ ЧАСОВ СРАЗУ):
- Отключите интернет. Запустите приложение, убедитесь в отсутствии браузера.
- Возьмите 5–10 мин аудио и ТОЧНО СООТВЕТСТВУЮЩИЙ DOCX/TXT.
- Выберите разбивку на 5 минут и запустите анализ.
- Получите DOCX первой части ещё до конца проверки.
- Проверьте точность таймкодов и прослушивание/перемотку замечаний.
- Сравните с оговорками, которые сами уже знаете: сколько нашлось и сколько
  ложных замечаний. Не делайте выводов о точности только по числу ошибок.
- Сделайте паузу и продолжите анализ. Затем проверьте на длинной записи.

СОСТОЯНИЕ: 56 программных тестов прошли в Linux. Настоящие модели и готовые
установщики на Windows/macOS в этом окружении не проверялись.
Сборка с большими моделями может завершиться ошибкой по памяти/диску или
упаковке зависимостей — это нужно будет исправлять по журналу GitHub Actions.

ПАПКИ В АРХИВЕ — ЭТО НЕ ПАПКИ, КОТОРЫЕ ДОЛЖЕН ВИДЕТЬ ПАПА:
- src: код приложения; tests: тесты; scripts: скачивание моделей при сборке
- .github: инструкция автоматической сборки Windows/Mac
В обычном готовом приложении пользователь работает с одним exe/app.
